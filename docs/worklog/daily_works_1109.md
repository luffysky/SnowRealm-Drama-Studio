## 我今天寫錯的東西

**這段放在最前面的位置，因為它比功能清單重要。**

### 1. 我交付了匯入，說它能用，而它在兩條路上靜靜地什麼都不做

子代理審出來的第一條：**對話框從來沒有把「這是哪一區」送給預覽端**。於是貼上
的內容（來源名字是「貼上的內容」）與檔名不含關鍵字的檔案都認不出區塊 → 伺服器
不回 `mapping` → 用戶端補成空陣列 → 每一欄都是「不匯入」→ 按下匯入，每一列都
被當空白列跳過 → **「已匯入 0 筆」**。

沒有錯誤訊息，因為確實沒有出錯。

而我在審查之前已經把這個功能交付給你並且說它能用。

### 2. 然後我花了半小時查一個不存在的 bug

修完之後寫了 `scripts/probe-import.mjs` 在真的瀏覽器裡走完整條路。它回報三條
紅，其中一條是「匯入回報的是 0 筆」——跟上面那個 bug 的症狀一模一樣。

**那是探針自己壞的。** 我把對話框的選擇器寫成：

```js
const DIALOG = '[role="dialog"], [aria-modal="true"]'
`${DIALOG} button`   // → '[role="dialog"], [aria-modal="true"] button'
```

逗號把它拆成**兩個**選擇器，第一個命中的是對話框那個 `div` 本身。它的
`innerText` 含「匯入」，所以「找匯入鍵」找到的是第 0 筆那個 div——對它
`.click()` 不會報錯，也不會有任何事發生。

查出來的方式是問它 `disabled` 是什麼，而 `JSON.stringify` 把那個欄位**整個吃
掉了**——`undefined` 不會被序列化。一個不見的欄位，才是那條線索。

### 3. 我在修 404 的同一輪裡寫了一個新的 404

儀表板新加的「內容存量」把劇本連到 `/projects/<id>/script`。磁碟上是
`scripts`，複數。**而 `check:links` 是綠的**——它看得懂 `href="/x"`、
`href={\`/x\`}`、`router.push()`，看不懂「路徑字面值包在函式呼叫裡、再透過
`href={row.href}` 展開」。

工具補上那個形狀之後它開始誤報（它只讀得到 `to('/novel')` 裡寫出來的那一段，
看不到小幫手補上去的 `/projects/<id>` 前綴），所以最後是**把路徑在原地寫全、
拿掉那層小幫手**。掃描器自己也加了一條自我檢查守著這個形狀。

### 4. 我寫了一支已經存在的工具

為了對帳 schema 與正式庫寫了 `scripts/check-db-shape.ts`，跑完才發現
`scripts/db-verify.ts` 做同一件事而且做得更細（連可空性與 enum 成員都比）。
刪掉了。**它唯一查出來而 `db-verify` 沒查的，是下面那條。**

### 5. 我的測試通過，而通過的理由是錯的

Z197 寫了一條「重算再跑一次不會多記一筆稽核列」。拿掉那道守衛之後它**還是
綠的**——因為 UPDATE 自己的 `where` 已經擋掉「什麼都不會改」的重跑了，根本輪
不到守衛上場。

真正會漏的是**字數往上爬**：UPDATE 會動（百分比 40 → 80）而狀態不變，少了守衛
作者每存一次檔趨勢圖就多一格「有進度」。補了一條會動到百分比的測試，這次拆掉
守衛會紅。

### 6. 我把同一支 patch 腳本跑了兩次

TODO.md 的 Z191／Z192 因此各多出一份。`check:todo` 當場抓到「重複：191、192」。

### 7. 我寫的規格當天就被推翻了

## Z194：一個鏡頭可以有好幾個人說話

`shots.speaker_id` 是**一個** uuid，所以「沈知味與錢管事在灶前拌嘴」本來只能拆
成兩鏡來記——而拆了之後鏡號、秒數與整張分鏡表都跟著失真。

改成 `shot_speakers` 關聯表，帶 `sort_order`：對白是一句接一句的，誰先開口有
差。鏡頭詳情的下拉換成**可複選的名牌**，選中的帶序號——一個看不出順序的多選框

匯入吃「沈知味、錢管事」，匯出用 `string_agg` 聚起來（join 的話一鏡三個人會變

**遷移是純新增的**：`drizzle/0036` 建表、搬舊資料，舊欄位原封不動。所以順序是
「先跑遷移，再部署」，中間不會有任何一邊壞掉。`shots.speaker_id` 留著，丟掉它
是 Z195（刻意沒做——欄位丟了就回不去，而留著不花什麼）。

`scripts/probe-speakers.mjs` 在真的瀏覽器裡點兩個名字、存檔、重新整理、數卡片

## 兩條不是我改出來的、但今天才被看見的錯

**懸浮對話在開發環境裡從來不渲染。** `restored.current` 那道守衛在 StrictMode
（dev 預設開著）下會把自己鎖死：第一次掛載設旗標並排一個 timer，cleanup 取消
timer，第二次掛載因為旗標已經是 `true` 直接 return——於是 `setReady(true)` 永遠
不跑，`if (!ready) return null` 讓整個元件消失。

正式站沒有雙重掛載所以看不出來。而「只有 dev 壞」的意思是：**在本機沒有人驗得
了這個元件的任何一行**，包括它那顆隱形的關閉鍵。我是在量不到那顆按鈕的時候撞
到它的。

**正式站上有兩行雙重編碼的亂碼。** 通話覆蓋層的「等對方接起⋯」「連線中⋯」與音
量滑桿的「通話音量」，磁碟上就是壞的。這種字**人不會發現**——它看起來像亂碼，
而我們每天在終端機裡看到的亂碼有一半是編碼設定造成的假象，所以真的壞掉的那幾
行會被當成假象放過去。

加了 `check:mojibake` 進提交門檻：把那一串倒推回位元組再當 UTF-8 讀，原本沒有
中文而倒推之後有，就是這個病。全專案掃完就那兩行。
