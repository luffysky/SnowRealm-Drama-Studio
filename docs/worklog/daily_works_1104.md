## 協定層面的兩個洞

這兩個不是打錯字，是設計時沒想到的情況。

### 收回／編輯不會即時同步

原本的即時協定只有一句話：「比這個序號新的給我」。
那處理新增沒問題，**處理不了修改**——收回不會改 `seq`
（改了訊息會跳到對話最底下，是錯的），所以對方永遠收不到。

加 `messages.updated_at`，串流改成抓「seq 比較新 **或** 這次同步之後被改過」。
實測：新訊息 196ms、編輯 163ms、**收回 95ms**。

### 一方掛斷另一方沒掛

串流那行是 `if (call) send('call', call)`。
掛斷之後 `activeCall` 回傳 null，所以**事件根本不送**，
對方就坐在一通已經結束的通話裡，計時器還在跑，直到重新整理。

改法不是「送 null」——null 沒有 id，分不出「你那通結束了」跟
「現在沒有通話」，後者在任何人撥號前一秒都成立，會把正在建立的通話拆掉。
改成送出最近一通的狀態不管結束沒，客戶端比對 id。

**附帶發現**：瀏覽器當掉或強制關閉不會送出結束的 PATCH，那一列會永遠停在
ACTIVE——而一個對話只允許一通進行中，所以那一列會讓之後**每次撥號**都收到
「已經有一通進行中的通話」，介面上沒有任何地方清得掉。
我自己的測試就留下了一筆這種殘留，正好撞到。

## 通話：從完全不通到確認需要 TURN

這是今天最長的一條線，而且**全靠實測推進**，我沒辦法單機驗證。

1. **第一版完全連不上**。接聽方收到 `offer` 時還沒建立 peer（要按接聽才建），
   `handle()` 直接 `return` 丟掉它——而訊號已經從資料庫刪了（投遞即刪）。
   握手永遠不會開始：電話會響、能接、計時器在跑、資料庫寫下「通話 40 秒」，
   **但兩邊沒有任何聲音畫面**。使用者的通話紀錄正好是這個形狀。

2. **視訊沒畫面**。本地預覽的 `<video>` 只在 active/connecting 時渲染，
   但 `srcObject` 是在 ringing 階段設的，那時 ref 是 null。
   鏡頭燈會亮、track 在流、畫面全黑。

3. **修好之後的診斷**：`sig=stable ice=disconnected host=2 srflx=1 relay=0`
   —— `sig=stable` 表示握手成功了，剩下的是真的穿不過 NAT。

4. **做了 Cloudflare TURN**：填兩個環境變數就自動生效，長期 key 只留在
   伺服器端，瀏覽器拿到的是後端 mint 的 6 小時短期憑證。
   費用 $0.05/GB、前 1000 GB 免費，而且只在點對點失敗時才用到。

**還沒驗完**：使用者要去 Cloudflare 開 key（Z103）。

## AI 助理：三件決定

使用者定的規格，我認為每一條都是對的：

1. **它不會自己插話，也不會偷讀**
   當天的做法是 `@` 或 `/` 觸發，住在兩個人的對話裡。
   **當天稍晚就推翻了**（見下方 Z106）——那個做法同時達成了「不插話」
   跟「讀不到你的追問」，後者不是代價是壞掉。
   現在改成它自己一頁，兩個人的對話它根本不在裡面。

2. **讀寫，但只能改副本**
   提案記下它當時看到的原值，人看 diff 才決定。
   目標在提案之後被改過的話套用會被擋下，要明確按「仍要套用」。

3. **套用一定備份**
   「取代」與「取代並備份」是同一條路徑。不備份而覆蓋，等於讓模型有權
   刪掉人寫的東西。

**實測三輪**：
- 一般訊息 `assistantTriggered=false`
- `@助理 有哪些作品` → 10.4 秒 / $0.056，三集的集名與字數完全正確
- `/outline 幫第四集寫大綱` → 39.7 秒 / **$0.42**，產生 1 個提案，
  **EP004 大綱當下仍是空的**

提案的理由提到「碼頭十份試單、兩百文欠租期限、許山河要人去查她、銅牌會變冷」

## 補做：AI 助理搬出共用對話（Z106／Z107）

日誌寫完之後你問「AI 助手在哪」，然後說「單獨弄出來，不要在同一個對話內」。
那是對的，而且理由比位置更深。

### 為什麼它不該住在兩個人的對話裡

1. **讀者不同。** 問模型的話跟跟暖寶說的話在同一條捲軸、同一個搜尋結果、
   同一個未讀數字裡。
2. **上下文不同。** 規格要求它「只讀自己那幾輪」，而共用一條對話時，
   唯一的分辨方式是正則比對訊息開頭是不是 `@` 或 `/`——
   **所以每一句沒加 handle 的追問，它都讀不到。**
   那不是保護隱私的代價，那是功能壞掉。
3. **歷史不同。** 一條對話串應該是一個題目；兩個人的對話是永不結束的流水帳。

### 做法

`/assistant` 自己一頁，側邊欄自己一個項目。每人可以開多條對話串，
一條就是一個題目，可以改名、刪除。進去直接打字就是對它說，不用 `@`。

底層沒有第二套實作：對話列多一個 `kind`（DIRECT／ASSISTANT）跟 `owner_id`，
訊息、附件、收回、編輯、搜尋、歷史分頁全部共用原本的 `lib/chat.ts`。

**守衛特別寫了一個 `assertOwnThread`，比成員資格嚴。**
因為我自己也是兩人對話的成員——光檢查成員資格擋不住
「把 DIRECT 的 id 丟進 run 跑一輪」。實測回 403。

「訊息」那邊打 `@助理` 或 `/` 會跳一行提示指去新頁面。
以前會動的東西現在不動了，就要說它搬去哪，不能默默沒反應。

### 指令重新設計

原本六個，其中 `/rewrite` 是錯的——它把「改情節」跟「改文字」混成一個，
而這兩件事要給模型**相反**的指示。一個指令等於每次都在猜使用者要哪一種。

拆成九個 ＋ `/help`：

| 只看（不產生提案） | 會提案 |
|---|---|
| `/ask` 問一件事 | `/write` 寫或續寫正文，可以動情節 |
| `/find` 在作品裡找東西 | `/polish` 潤稿，**明確禁止動情節** |
| `/recap` 回顧某幾集 | `/outline` 寫或改分集大綱 |
| `/check` 挑矛盾 | `/character` 補角色設定 |
| | `/world` 補世界觀 |

`/check` 是新的，大概也是最有用的一個：120 集的長度下，
「第 40 集跟第 9 集打架」人自己很難抓，而這正是模型擅長的。它只報告不提案。

右上角加了問號，打開是完整說明，依「只看／會提案」分組，
每條有用法、在做什麼、以及可以直接填進輸入框的範例。
`/help`、輸入框選單、問號面板**三者都從同一個 `SLASH_COMMANDS` 陣列長出來**，
不會改了指令名之後說明還停在舊的。

## 補做這一段又抓到三個

### 1. Drizzle 在 select 清單裡不會加表名——相關子查詢靜默失效

對話串列表要顯示「最後一句話」跟「訊息數」，我寫成相關子查詢：

```ts
where ${messages.conversationId} = ${conversations.id}
```

編出來是：

```sql
where "conversation_id" = "id"
```

**兩個名字都在子查詢裡解析掉了**，等於每一列都在比
`messages.conversation_id = messages.id`。不報錯、不是空結果，
就是一個永遠為假的關聯——每條對話串都顯示「還沒說話」、訊息數 0。

Drizzle 在 **`where` 子句裡會**加表名（`"conversations"."kind" = $1`），
在 **select 清單裡不會**。所以同樣的寫法在這個專案其他地方是對的——
我逐一查過 `asset-browser.ts`、`episodes.ts`、`usage.ts`、`writing.ts`，
它們不是有 join（會加表名）就是寫在 where 裡，都沒問題。

改成三個查詢：主表 + `group by` 算數量 + `distinct on` 取最後一句。
是測試抓到的，不是我看出來的。

### 2. 懸浮球蓋住送出鍵

助理頁面的送出鍵在右下角，懸浮對話球也在右下角。
**手機上球幾乎整個蓋住送出鍵**——字打得進去，按鈕按不到。

藏掉球不是答案：它是來電會響的地方，而「只有正在看那一頁才會響」
正是前面剛修好的 bug。

改成頁面把自己底部工具列的高度寫成 `--dock-height`，懸浮元件讓開。
用 `ResizeObserver` 即時量，因為輸入框可以拉大。
其他頁面沒設這個變數，行為完全不變。

### 3. `/help` 回報「花了錢」

`/help` 是固定文字，根本不會進模型。但它原本在 `runAssistant` 裡提早 return，
而路由對任何進到 `runAssistant` 的東西都標 `spent: true`。
錢沒花，但那個旗標是給介面判斷要不要顯示費用的，它說的是假的。

把 `/help` 移到路由，跟「打錯的指令」放在一起——兩條免費路徑現在在同一個地方。
實測兩條都 `spent=false`。

順帶修掉：打錯的指令不再被拿去當對話串的標題
（測的時候真的出現一條叫「第四集」的對話串，來源是我打錯的 `/outlinee 第四集`）。

### 測試留下的東西都清掉了

助理的測試對話串全刪。兩人對話裡那一則測試訊息——
收回只是把 `body` 清空留著列，所以它會在你們的對話裡顯示「訊息已收回」——
直接從資料庫刪掉，序號歸零。
