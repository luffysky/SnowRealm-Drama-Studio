## 我今天寫錯的東西

**這一段放在功能清單前面，因為它比功能清單重要。而今天這一段特別長。**

### 1. 我看了規格，然後把它扔在旁邊重寫了一遍

老闆那份 HTML 裡寫死了三樣東西：首席編劇總監那段 persona、14 條審核準則、12 項
skills。**我一樣都沒接進提示詞**，自己另外寫了一套指令。

是用戶問「你沒看html?」我才回去看的。我讀了——整份 392 行都讀了——但我只用了它
的**結構**（九個分頁、雙視角的概念），沒有用它的**內容**。

補回來的時候做對了一件事：規則與畫面讀**同一份**（`audit-rules.ts`），勾掉一條
會真的從提示詞裡消失。各抄一份的話，改了提示詞而畫面還在講舊的那一版——那正是
`RAIL_HELP` 手抄 `navigation.ts` 標籤的病，而它已經缺了兩項沒人發現。

### 2. 我做了一份唯讀的報告，而讀完的人沒有地方問問題

用戶問：「但是輸入框呢 這Agent沒法溝通? 如果老闆要提問誰回答」。

對。暖寶讀完想問「第 7 集這個爽點我覺得不夠」，整頁沒有一個地方可以問。我把
「整理給我看」理解成「產生一份報告」，而她要的是一個**助理**。

### 3. 回答印出一堆星號

第一版用 `whitespace-pre-wrap` 把模型回的原字串直接印出來，所以畫面上是
`**許家舊帳**` 這種東西。用戶的話：「回答還帶md格式 我老闆看不懂」。

而**專案裡早就有 `RichText`**（助理那邊用的），它把 markdown 的一個小子集渲染成
React 節點。我沒去找就自己寫了一個更差的。

### 4. 字太小，被退兩次

第一版整頁 10–11px。第二次拉到 15px 還是被退。這一頁的內容是**拿來讀的**，不是
介面上的標籤——它跟專案其他頁面的密度本來就不該一樣，而我套了同一套。

### 5. 我自己把 token 上限調低，整次呼叫作廢

第一版傳 `maxTokens: 6_000`，而 `NOVEL_REVIEW` 本來的上限是 12,000。`effort:
high` 的思考把那 6,000 全部用完，**一個字的內容都沒留下**。適配器正確地丟了
「模型把輸出額度用在思考上」，而那 72 秒的錢照付。

省那幾千 token 的代價是整次呼叫作廢。

### 6. 我花了兩次 API 呼叫，查一個不存在的「卡住」

瀏覽器驗收時連續兩次截到「還在轉圈」，我以為請求沒回來。

**是我的偵測寫錯了**：我用 `/目前的主線/` 掃 `document.body.innerText`，而頁面上
方那四個問題裡就有「目前的主線與人設」——第一圈就命中，然後在模型還在跑的第七秒
截圖。要等的是真的被畫出來的那個 `h3`。

### 7. 最難看的一條：我回報了一個沒驗過的結論

查分鏡那個 bug 時我 grep 出 12 處同樣的寫法，然後跟用戶說「12 處都壞了，素材的
預覽圖與波形一律顯示為沒有」。

**那是推論，不是量測。** 實際拆掉修法再量一次：

| 我說的 | 實際 |
| --- | --- |
| 12 處都壞 | **2 處壞**（5 個欄位） |
| 預覽圖與波形顯示不出來 | 12 張預覽圖、5 個波形**一次都沒少過** |

原因是 drizzle 的渲染**看上下文**：單表 select 才會漏掉表名，`where` 子句裡跟有
join 的 select 都是帶表名的。`asset-browser` 有兩個 join，所以它從來沒壞過。

這跟 11-05 那次「宣稱一個消費者存在而沒去 grep」是同一個錯，只是換了一層：這次
我 grep 了，但沒有**跑**。

## Z199：分鏡的「0 鏡」

drizzle 渲染內插進 `sql` 模板的欄位物件時，**加不加表名要看上下文**：

| 形狀 | 渲染 |
| --- | --- |
| 單表 select（沒有 join） | `"id"` ← 會出事 |
| `where` 子句裡 | `"episodes"."id"` |
| select 但有 join | `"assets"."id"` |

第一種的子查詢裡，那個光禿禿的 `"id"` 綁到最內層那張表——它也有 `id` 欄。條件變
成 `s.episode_id = s.id`，永遠不成立。**Postgres 不報錯，它只是回 0**。

真正壞的兩處：`storyboardIndex` 的四欄（鏡頭數／秒數／已核准／有無劇本），
`listOutline` 的每集字數。

兩道鎖：`check:subquery` 擋寫法（只抓被比較的那一側、只認從 schema import 的名
字，不然 `unnest(${projects.tags})` 的標籤搜尋會被誤報），
`tests/subquery-counts.test.ts` 守數字。兩個都做過破壞驗證。

## Z200：存起來，與遷移執行器

主線整理、每一集、整串問答各有一顆「存起來」，存完在下面「存起來的」裡收合著，
點箭頭展開。**存的是結果不是模型回的原字串**——原字串要重新解析才畫得出來，而解
析器會改。

順手做了一支遷移執行器，因為 `drizzle-kit migrate` 在這個 repo 上是壞的：
`_journal.json` 只記到 0015，0016 之後那二十幾支手寫的遷移從來沒進過 journal。它
不但不會跑新的，在一座**新**資料庫上還會安靜地少建二十幾支的東西。

新的那一支不看 journal，直接看 `drizzle/*.sql`，帳記在
`public.applied_migrations`（刻意不跟 drizzle 共用那張表）。**跑過的那一支被改掉
時叫，然後停**——已經套用過的遷移再跑一次，輕則報錯重則把資料弄壞。

雜湊先把 CRLF 統一成 `\n` 再算：這個 repo 在 Windows 上會被 git 轉行尾，不統一的
話同一個檔案在兩台機器上算出兩個雜湊，每次都喊「被改過了」，喊久了就沒人看了。

五條路都在測試庫上走過：認列、跳過、偵測改動、`--accept`、真的跑一支。
